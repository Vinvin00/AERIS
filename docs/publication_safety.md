## Limits

This is a heuristic scan, not a guarantee.

- Regexes describe common token shapes; entropy-based or provider-specific secrets can be missed.
- Binary blobs are checked by name and size, not content.
- Not covered: reflog, stashes, unreachable objects, other clones or forks, and GitHub-side data
  (issues, PR comments, Actions logs, releases, settings).
- Rights are a human judgment. No third-party footage or weights are bundled. The FGVC sample, the
  YOLOX weights and dependencies each carry their own terms (see `docs/dataset.md`, `models/README.md`),
  and no project license is selected, so the code is "all rights reserved" by default.
- The tool and this audit do not rewrite history, change repository visibility or contact GitHub.

## Before making the repository public

1. Choose a project license (or knowingly leave it unlicensed).
2. Decide whether the personal email in history is acceptable; if not, rewriting history is a
   separate, owner-approved task.
3. Re-run the audit on the exact commit being published and review any new finding.
4. Inspect the GitHub-side data listed above, which this audit cannot see.
